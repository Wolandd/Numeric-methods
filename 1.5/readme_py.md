# Часть 1.5. QR-разложение и QR-алгоритм — пояснение к main.py

**Задание:** самостоятельно реализовать QR-разложение, затем на его основе найти все собственные значения вещественной квадратной матрицы с заданной точностью. Матрица может быть несимметричной, а собственные значения — комплексными.

## Что ищем и какие обозначения нужны

Матрица — таблица чисел: `A[i][j]` означает элемент строки `i`, столбца `j`. Индексы начинаются с нуля. Главная диагональ — `A[i][i]`; ниже неё находятся элементы с `i > j`. Первая поддиагональ проходит непосредственно под ней: `A[i + 1][i]`.

Собственное значение `λ` — число, для которого существует ненулевой вектор `w`, удовлетворяющий `A·w = λ·w`: действие матрицы на этот вектор равносильно умножению на одно число. Ищем **все n значений λ с учётом повторений**; сами векторы `w` программа не вычисляет.

| Обозначение в коде | Смысл |
|---|---|
| `A`, `n` | Исходная матрица и размер `n = len(A)`. |
| `I` | Единичная матрица: единицы на диагонали, остальные элементы нулевые. Умножение на неё ничего не меняет. |
| `Q`, `R` | Матрицы разложения `A = Q·R`. У `R` нули ниже диагонали; `Q` ортогональна: сохраняет длины, а `Q^T` выполняет обратное преобразование, поэтому `Q^T·Q = I`. |
| `T`, `norm_x` | `T` означает транспонирование — обмен строк и столбцов. Норма — длина вектора: корень из суммы квадратов его элементов. |
| `k`, `v`, `H` | Обрабатываемый столбец, вспомогательный вектор и матрица отражения Хаусхолдера. `v` — не собственный вектор. |
| `current_A`, `final_A` | Матрица во время QR-итераций и итоговая матрица в `main()`. |
| `eigenvalues`, `block_sizes` | Найденные значения и размеры диагональных блоков, например `[2, 1]`. |
| `epsilon`, `iterations`, `converged` | Заданная точность, число QR-итераций и признак выполнения условий остановки. |

Знак `·` ниже означает матричное умножение: порядок множителей важен. `≈` — приближённое равенство.

## Как читать программу по ходу решения

**1. Начинаем с `main()`, вызванной внизу файла.** Задаём матрицу варианта и `epsilon = 0.000001`. Проверяем квадратность, `n >= 2`, конечность чисел и положительную точность. Копирование строк через `row.copy()` сохраняет исходную матрицу для проверок.

**2. Переходим в `qr_decomposition(A)`.** Цель — получить `A = Q·R`. Начинаем с `R = A`, `Q = I`. Цикл `k` последовательно обрабатывает столбцы от `0` до `n - 2`:

- Берём часть столбца `x = [R[k][k], ..., R[n-1][k]]`. В `sum_squares` складываем квадраты её элементов, затем `math.sqrt()` даёт `norm_x`. Полностью нулевую часть столбца пропускаем.
- Выбираем `sign`: `+1` при неотрицательном первом элементе, иначе `-1`. Строим вектор `v` по формуле (1.30) методички:

  ```text
  v[k] = R[k][k] + sign * norm_x
  v[i] = R[i][k] для i > k; до k стоят нули.
  ```

- Считаем `v_norm_squared` — сумму квадратов компонентов `v`. Создаём `H = I` и по формуле (1.29) изменяем каждый элемент:

  ```python
  H[i][j] = H[i][j] - 2 * v[i] * v[j] / v_norm_squared
  ```

  Это запись `H = I - 2vv^T/(v^T v)`: числитель содержит попарные произведения компонентов, знаменатель — сумму их квадратов. Такое отражение обнуляет выбранные элементы столбца ниже диагонали.

- Выполняем `R = multiply_matrices(H, R)` и `Q = multiply_matrices(Q, H)`. Первая строка преобразует матрицу, вторая накапливает отражения. Отражение обратно самому себе; указанный порядок накопления обеспечивает `Q·R ≈ A`.

После обработки столбцов `R` становится верхней треугольной, `Q` — ортогональной. Малые остатки вместо точных нулей возникают из-за вычислений с дробными числами.

**Вспомогательные функции:** `multiply_matrices()` для каждого элемента результата складывает произведения строки левой матрицы на столбец правой; `transpose_matrix()` меняет строки и столбцы местами. Готовых математических алгоритмов из библиотек нет.

**3. Возвращаемся в `main()` и проверяем разложение.** Вычисляем `Q·R` и `Q^T·Q`. Переменные `qr_error` и `orthogonal_error` содержат максимальные отклонения от `A` и `I`. Если проверки не пройдены, дальнейшие вычисления прекращаем.

**4. Запускаем `qr_algorithm(A, epsilon)`.** Создаём `current_A` и счётчик `iterations = 0`. На каждой итерации выполняем:

```python
Q, R = qr_decomposition(current_A)
current_A = multiply_matrices(R, Q)
iterations = iterations + 1
```

Сначала раскладываем текущую матрицу как `Q·R`, затем перемножаем в обратном порядке. Получается `A_new = R·Q = Q^T·A_current·Q`: та же операция в другой системе координат. Поэтому собственные значения сохраняются, а форма матрицы постепенно упрощается.

## Как получаем действительные и комплексные корни

**5. После каждого QR-шага вызываем `eigenvalues_from_blocks()`.** Вещественная матрица с комплексными корнями не обязана становиться треугольной: на диагонали могут остаться квадраты **2×2**, называемые блоками. Над блоками допускаются любые элементы, под ними должны быть малые.

Функция проверяет элементы ниже первой поддиагонали, затем просматривает матрицу сверху вниз:

- Малый элемент `A[i + 1][i]` позволяет выделить блок **1×1**: собственное значение равно `A[i][i]`.
- Значительный элемент указывает на возможный блок **2×2**. Следующий поддиагональный элемент должен быть малым: иначе получился ещё не разделившийся блок размером минимум 3×3.
- Если допустимая структура не получена, возвращаем пустые списки и продолжаем итерации.

Для блока `[[a, b], [c, d]]` решаем обычное квадратное уравнение:

```text
λ² - (a + d)λ + ad - bc = 0
D = (a - d)² + 4bc
D >= 0: λ₁,₂ = (a + d ± sqrt(D)) / 2
D < 0:  λ₁,₂ = real_part ± imag_part·i
        real_part = (a + d) / 2; imag_part = sqrt(-D) / 2
```

Здесь мнимая единица `i` удовлетворяет `i² = -1`. В Python `complex(real_part, imag_part)` создаёт комплексное число; `.real` и `.imag` дают его части. Парные корни имеют одинаковую действительную часть и противоположные мнимые. После блока индекс увеличиваем на 2, после одиночного элемента — на 1.

## Когда останавливаемся и как проверяем ответ

**6. В `qr_algorithm()` проверяем сразу весь результат.** Для малости элементов используем `element_tolerance = epsilon * matrix_scale`, где `matrix_scale` — максимальный модуль элемента исходной `A`. Для нашего варианта этот порог равен `8·10⁻⁶`.

Для успешного завершения нужны все `n` корней, одинаковые `block_sizes` на двух соседних итерациях и изменение каждого корня не больше `epsilon`. Предыдущие результаты хранятся в `previous_values` и `previous_blocks`; при недопустимой структуре они сбрасываются. Сравниваем именно корни: элементы комплексного блока могут продолжать меняться.

Возвращаем `current_A, eigenvalues, iterations, True`; в `main()` первый результат называется `final_A`, последний — `converged`. Если лимит `10000` исчерпан, возвращаем пустой список корней и `False`. Обычный QR-алгоритм без сдвигов может не сходиться. Проверки норм и конечности чисел также останавливают вычисления при невозможности безопасного деления или переполнении.

**7. В конце `main()` выводим ответ и контрольные проверки.** `trace_A` — сумма диагонали исходной матрицы; с ней сравниваем `values_sum`, сумму найденных корней. Для заданного варианта дополнительно сравниваем с контрольными корнями и проверяем `values_product ≈ 306`. Контрольные числа используются только после вычисления ответа. Эти проверки полезны, но сами по себе не доказывают точность каждого корня; `epsilon` задаёт критерии остановки.

Для нашего варианта за **38 итераций** получено:

```text
λ₁ =  4.8315686404
λ₂ = -5.4157843202 + 5.8311877043i
λ₃ = -5.4157843202 - 5.8311877043i
```

Сумма близка к `-6`, произведение — `306.0000067908`. Максимальное отклонение от контрольных корней — около `1.81·10⁻⁷`; ошибки `A ≈ Q·R` и `Q^T·Q ≈ I` — около `1.78·10⁻¹⁵` и `1.11·10⁻¹⁶`. Порядок корней не важен. Округление применяется только при печати.
